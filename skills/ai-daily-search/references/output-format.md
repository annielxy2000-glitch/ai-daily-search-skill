# 分类事件清单（默认格式）

适用：用户要“整理 / 盘点 / 列出”某领域或某主体在一段时间内的事件。

```markdown
# {领域或主体}事件（{起始日期}—{结束日期}）

## 一、技术与产品

**（一）模型、产品与工具发布**

- 2026年9月14日，{主体}{做了什么}，{一到两处关键细节：数字、对比，照原文口径}。（[日报](url)）

**（二）研究与开源**

**（三）部署、测试与量产**

## 二、商业与资本

## 三、政策与治理

## 四、观点与讨论

检索范围：{起}–{止}；检索词 {…}；过滤 {标签/类型}；去重后 {N} 个事件。
```

写法：

- 每条一句完整的话，以“YYYY年M月D日，”开头，主体在前、动作紧跟，再补一到两处关键细节。一条里有几件事就写清楚，如“发表两篇论文，一篇为……，另一篇为……”，或用分号接续。
- 同一事件的后续写在同一条里：“……；10月11日，作者又宣布……”。
- 按事件性质分类，不按日报板块（早期日报的板块叫“前沿信号/市场动态”，没有按技术、商业、政策拆开）：
  - 技术与产品：模型、产品、工具、论文、开源、基准、部署、量产、测试。小类按需要增删，某领域条目多时可加小类（如“自动驾驶”），没有条目的类不写。
  - 商业与资本：融资、估值、上市与并购、财报、投资与战略合作、供应链合同、行业融资数据。
  - 政策与治理：政府、监管、标准机构的政策、法规、标准、会议。
  - 观点与讨论：具名人物的判断和争论，写明身份和“称/认为”。
- 每类内部按日期从早到晚。
- 擦边条目句末标“（边缘）”，排在同类最后或照日期排。
- 每条句末给日报链接；用户要求时再加原始来源。
